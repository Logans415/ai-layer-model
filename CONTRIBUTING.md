# Contributing

Bring a concrete example and evidence. For a new tool mapping, identify the item/version, its actual role, primary anchor or set, other confirmed/conditional layers, dependencies, and source links. Explain where a boundary is unclear.

For a model change, describe the problem, the proposed boundary or definition, and how existing examples would change. Keep model revisions distinct from product-version updates. Retain author and contributor attribution.

Submit a public issue or pull request. Do not include private code, credentials, internal hostnames, employer information or sensitive prompts. Read SECURITY.md before reporting a concern.

By contributing model/write-up material you agree to its CC BY 4.0 scope; by contributing skill instructions or implementation code you agree to the MIT scope described in LICENSE. Only submit work you are entitled to share.
